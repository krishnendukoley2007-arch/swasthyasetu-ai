How It Works

From Chest to Screen.
In Under a Second.

💓

Skin → Chip

Two electrodes capture a ~1 mV heart signal. The AD8232 amplifies it 100×, filters noise, outputs a clean 0–3.3V wave.

⚡

Sampled 250× per Second

A hardware timer fires every 4 ms — a metronome that cannot be distracted. Each tick reads the analog voltage as a 12-bit number.

📦

Packed into 20-Byte Envelopes

Every 8 samples are sealed into a BLE-friendly packet. 31.25 envelopes per second — a steady stream of postcards.

📡

Bluetooth LE Flight

ESP32's radio pushes each envelope wirelessly. No pairing dance, no cables. The phone subscribes once and data flows.

🔍

Phone Catches & Checks

The app is suspicious by design: wrong length → discard. Sequence gap → count it and tell the user. Out-of-range vitals → reject.

🎯

Triage & Explanation

Rule engine evaluates thresholds → risk band → plain-language explanation. Offline-first, labelled honestly, actionable.

The Full Picture

How It Actually Works.
All of It.

No slogans. This is the real chain from a heartbeat on the skin to a decision on screen — and who can do what with it.

A

The board: SSAI-SENSE-01

ESP32 + AD8232 ECG front-end + MAX30102-style optical pulse + IR temperature. Samples ECG at 250 Hz, packs frames of 8 samples every 32 ms, and broadcasts over BLE. A 20-byte telemetry frame carries HR, SpO₂, temperature, RR interval, signal quality, lead-off flag and battery — nothing computed, only measured.

B

The link: BLE, verified per frame

The phone subscribes to three characteristics (vitals, ECG, motion). Every frame is checked: wrong byte count → dropped. Sequence gap → counted and shown. Frame rate stalls 5 s → the banner says the board stopped, not that everything is fine. Gap in a trace renders as a gap, never a bridged line.

C

The app: measure → verify → score

A 30-second screening captures vitals + the raw ECG strip. The deterministic risk engine (not AI) scores it 0–100 — heart rate bands, SpO₂ floors, fever rules, symptom flags — and lands it in GREEN / YELLOW / RED. RR intervals are measured from the actual strip: peak detection with a 200 ms refractory window and a flat-line guard, so noise yields "no plot", not a fake one.

D

Measured vs estimated

Blood pressure and glucose are estimates derived from pulse timing — always rendered in violet with an EXPERIMENTAL tag and "confirm with calibrated devices". The strip and vitals are measured. The two never share a colour or a label, so nothing experimental can pass as a reading.

E

Who signs in, and how

Patients (Google / phone OTP) see their own health: their band, their trends, their SOS. Clinicians see the queue: patients, history, community aggregates. ASHA workers get one-tap offline login that never touches a server. Demo mode is real software with generated data — always labelled DEMO, never storable as a measurement.

F

Where the data lives

On the phone: SQLite (Drift), ECG strips as gzipped files. Syncs to Firestore only with consent, and the sync queue is visible as a badge — never silent. The web dashboard (this site → Open Web App) reads the same Firestore and talks to the same board over Web Bluetooth. Nothing leaves a device without a name, a time, and a provenance flag attached.

What this is not

It is not a certified medical device. It screens; it does not diagnose. The risk band says "who needs attention first", not "what disease". A RED result means seek a nurse or doctor now — the app says so on the screen where the result appears, in the patient's own language.

Triage Engine

Deterministic. Auditable.
Never Guesses.

Same vitals always produce the same band. No model inference. Every result traceable to a threshold.

0–30

🟢 Routine

No action needed. All vitals within normal range.

31–60

🟡 Needs Attention

Review today. One or more warning thresholds breached.

61–100

🔴 Urgent

Escalate now. Critical threshold or critical-floor rule triggered.

🛡️ Critical Floor

Any single life-threatening reading floors the score at 61 — it cannot be averaged away by normal vitals.

👶 Vulnerability-Aware

Thresholds shift for elderly, infants, pregnant, chronic, and immunocompromised patients.

🧪 Demo-Safe

Demo readings carry an immutable isDemo flag and can never contaminate real screening records.

Design Philosophy

Honest by Design.
Not by Accident.

01

One-Way Provenance

Data goes measured → demo-flagged, never the reverse. isDemo makes it structurally impossible for simulated readings to masquerade as real.

02

No Fabricated Gaps

A missing value renders as —. Never 0, never an interpolation, never a plausible-looking guess. The display says "I don't know."

03

Rules Decide, AI Explains

The risk engine is the only code that sets the triage band. Gemini can explain but can never change the result.

04

Tested Where It Hurts

The risk engine is auditable end-to-end: 445 tests cover the boring failure modes — layout overflow at 2.0× font scale, map honesty when consent is off, threshold boundaries.
